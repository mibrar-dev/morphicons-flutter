Icons that morph
like rigid bodies,
not melting shapes.

Morphicons is a Flutter package built on a similarity-transform solver. Given any two stroke icons it decides — automatically — whether the transition is a rotation, a scale or a plain morph, then interpolates in polar space so an arrow rotates as an arrow. No keyframes. No hand-declared correspondence.

The engine

A solver, not a tween library.

Eight stages, all pure math, all Flutter-free until the very last paint call. A faithful Dart port of the morphicons core — validated against the original at float64 precision.

stage 1–2

Normalize everything to cubics

A from-scratch SVG d-string parser and normalizer: lines, circles, ellipses, rects, polylines, polygons and arcs become chains of cubic Béziers. Relative commands, H/V/S/T shorthands, packed arc flags like a1 1 0 0110 — the full mini-language. dart:ui.Path is never touched until paint time.

stage 3

Corner-anchored resampling

Each subpath is resampled to N = 64 points, equidistant by arc length (8-point Gauss–Legendre quadrature). Corners are anchored as exact sample indices, so they stay sharp mid-morph.

stage 4

Correspondence search

Both traversal directions, all circular start rotations, subpaths matched by dist(centroids) + 0.35·|ΔL|. Unequal counts duplicate the nearest subpath — shapes divide, they never vanish.

stage 5

2D Procrustes, closed form

The optimal rotation θ*, scale σ* and translation per subpath — ten lines of arithmetic, no SVD. A global hybrid pass makes rigid icons rotate as one block.

stage 6

Polar interpolation

Motion is decomposed into translation + rotation(t·θ*) + scale(σ*ᵗ) applied to the residual — never a raw x/y lerp. That is why circles don't shrink when they rotate.

stage 7

Physical springs

Damped harmonic oscillator, 1/240 s substeps, three presets. Mid-flight interruptions re-plan from the current shape and preserve velocity — rapid re-triggering never jumps.

stage 8

Canonical snap + zero flash

In flight the painter emits a cheap polyline; on settle it snaps to the exact canonical paths of the target icon. The first frame is already the final shape — plan building is synchronous and takes ~0.35 ms. A resting morph is pixel-identical to a static icon.

Compatibility

Any stroke icon. Any source.

Morphicons consumes raw SVG d strings or Lucide-style [tag, attrs] nodes. If you can describe it as a path, it can morph.

Works with

  • Lucide1,500+ icons shipped as generated constants in morphicons_lucide
  • Feathersame 24×24 stroke grammar as Lucide
  • Tabler Icons24×24, stroke 2, round joins
  • Heroicons outline24×24 stroke variant
  • Iconoir, Phosphor regularuniform-stroke sets
  • Any custom d stringhand-drawn paths, logos, your own icon set
  • Off-grid iconsfitIcon() re-grids 16/20/32/48 viewBoxes onto 24×24

Best results: single-weight strokes, fill="none", round caps and joins, coordinates in a square viewBox. The solver was designed for exactly this grammar.

Lucide source icons are ISC licensed. Morphicons keeps upstream credit and license notices with generated data.

Out of scope

  • Filled / solid iconsMaterial Symbols filled, emoji-style glyphs
  • Multi-color or gradient iconsthe pipeline is geometry-only, single stroke color
  • Text or raster contentpaths only
  • Masks and clip pathsnot part of the icon grammar the solver assumes

Rule of thumb: if the icon looks right rendered as one uniform stroke, it will morph well. Icons with wildly different topology still morph — the solver just interpolates the residual — but the rigid-body magic shows on stroke sets with shared structure.

Documentation

Three modes, one widget.

Install

flutter pub add morphicons_flutter
flutter pub add morphicons_lucide   # optional icon data

1 · Uncontrolled

Change icon, the widget animates.

MorphIcon(
  icon: isOpen ? MorphIconsLucide.x : MorphIconsLucide.menu,
  spring: SpringPreset.snappy,
)

2 · Controlled

Explicit progress — for scrubbers and drag gestures.

MorphIcon.controlled(
  from: MorphIconsLucide.menu,
  icon: MorphIconsLucide.x,
  progress: dragProgress, // 0..1, >1 extrapolates
)

3 · Imperative

Sequenced morphs through the state object.

final key = GlobalKey<MorphIconState>();
MorphIcon(key: key, icon: MorphIconsLucide.menu);

key.currentState?.morphTo(MorphIconsLucide.check); // animates
key.currentState?.set(MorphIconsLucide.x);          // jumps

Behavior parity

  • First frame paints the exact canonical shape — no async warm-up, no flash
  • MediaQuery.disableAnimations → instant swap
  • One shared Ticker scheduler steps every active spring
  • Canonical snap on settle — resting icons are pixel-identical to static ones
  • Interruptions re-plan from the current shape, velocity preserved

Pure-Dart core

morphicons_core has zero Flutter imports and zero dependencies — dart:math and dart:typed_data only. Run it on the Dart VM, test it headless, or drive it from a non-Flutter target:

final plan = planBetween(menuD, xd);
final out = allocOutputs(plan);
interpPolar(plan, 0.5, out);
final d = serialize(out);

Questions

Will it work with IconData / Material icons?

Not directly — IconData glyphs are compiled into the font and can't be introspected. Morphicons needs path data. Use any stroke icon set that ships SVG paths (Lucide, Tabler, Feather, Heroicons outline) or convert your own right on this page with the converter above — for whole icon packs, tool/extract_icons.mjs in the repo reads the installed Lucide modules and emits a complete Dart data file.

Does it work on all Flutter platforms?

Yes. The core is pure Dart; the widget layer uses only CustomPaint and Ticker. iOS, Android, web (CanvasKit and HTML), macOS, Windows, Linux.

How fast is it?

Plan building takes ~0.35 ms for a two-subpath pair (the upstream reference measures 0.01–0.42 ms). Per frame the painter only walks preallocated buffers — no heap allocation beyond the emitted Path. A shared scheduler means 50 concurrent morphs still cost one ticker.

Can icons have different numbers of subpaths?

Yes. The nearest subpath is duplicated to balance the counts — visually it reads as cell division rather than a shape vanishing.

Is this a fork of the upstream project?

It's a faithful transcription of the mathematics, validated against golden fixtures dumped from the original implementation (θ/σ parity at 4.4e-16). Upstream is credited in the LICENSE and READMEs; both are MIT.
